Remember a phrase, not the file name?

CherryQuery looks through what’s written in your documents, so you can find the right file even when you’ve forgotten what you called it.

Searches inside your files

Word, Excel, PowerPoint, PDF, OpenDocument, RTF, notes, data files and source code — all searched by what they say.

See the match in context

Each result shows the file name, last modified date and time, and a content preview with your keyword highlighted.

Precise when you need it

Put a phrase in "quotes" to match whole words, and combine terms with AND, OR and NOT.

One shortcut away

Press Ctrl + Shift + Space from anywhere to open CherryQuery, or pick your own hotkey. It waits quietly in the taskbar.

Fast, gentle indexing

A local index makes searches quick. Files changed in the last 7 days are indexed first; older files wait until your computer is idle.

Private by design

No uploads, no accounts, no analytics, telemetry or ads. Light and dark themes, and an interface in nine languages.

Good to know

A few details about what CherryQuery searches and how.

Which folders are searched?

Your Documents folder by default. Folders like node_modules, .git, .svn, $Recycle.Bin and System Volume Information are skipped, as are Office’s temporary ~$ files. You can adjust indexed file types and excluded folders in Settings.

How quickly do new or changed files show up?

Search reads a local index rather than the files themselves, so new or changed files appear once they’re indexed. Recently changed files go first. and the folder is re-checked every 10 minutes while the app is open.

Are there size limits?

Documents (Word, Excel, PowerPoint, PDF, OpenDocument, RTF) up to 50 MB and test files up to 5 MB are searched; larger files are skipped. Up to 2 million characters of text are indexed per file.

Can it read scanned or password-protected files?

No. Scanned PDFs without a text layer won’t match because text recognition (OCR) isn’t used, and password-protected documents can’t be read.

How does matching work?

Matching is case-insensitive by default. Use double quotes for whole-word matches — "cat" matches “cat” but not “category” — and combine words with AND, OR and NOT. Text files are read as UTF-8.
